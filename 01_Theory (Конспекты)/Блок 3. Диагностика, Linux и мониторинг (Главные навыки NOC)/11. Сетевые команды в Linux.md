# 11. Сетевые команды в Linux (iproute2, ss, firewall)

Теги: #cli #linux #networking #iproute2 #ss #iptables #ethtool #conntrack #base

## Суть простыми словами
В современном Linux устаревший набор сетевых утилит `net-tools` (`ifconfig`, `route`, `netstat`, `arp`) полностью заменен на более быстрый и функциональный пакет **`iproute2`** (`ip`, `ss`). Умение быстро проверить интерфейсы, маршруты, сокеты и правила файрвола в консоли Linux — один из главных практических навыков NOC-инженера на собеседовании и дежурстве.

---

## Таблица замены устаревших команд на современные

| Задача | Устаревшая команда (`net-tools`) | Современная команда (`iproute2`) |
| :--- | :--- | :--- |
| **Посмотреть IP-адреса и интерфейсы** | `ifconfig -a` | **`ip a`** (или кратко **`ip -br a`**) |
| **Посмотреть статистику ошибок на порту** | `ifconfig eth0` | **`ip -s link show eth0`** |
| **Посмотреть таблицу маршрутизации** | `route -n` / `netstat -rn` | **`ip r`** (`ip route show`) |
| **Посмотреть ARP-таблицу (соседей L2)** | `arp -n` | **`ip neigh`** (`ip n`) |
| **Посмотреть открытые порты и сессии** | `netstat -tulnp` | **`ss -tulnp`** |

## 1. Пакет `iproute2`: управление интерфейсами, маршрутами и ARP

### Уровень L1–L2: интерфейсы, VLAN и соседи
```bash
# Краткий и читаемый список всех интерфейсов, их статусов (UP/DOWN) и IP-адресов
ip -br a

# Посмотреть MAC-адреса, MTU и физический статус всех сетевых карт (включая VLAN-интерфейсы вида eth0.10)
ip -br link

# Посмотреть счетчики ошибок (RX/TX errors, dropped, overruns) на интерфейсе
ip -s -s link show eth0

# Включить или выключить сетевой интерфейс
sudo ip link set eth0 up
sudo ip link set eth0 down

# Посмотреть таблицу ARP / NDP (состояние REACHABLE, STALE, FAILED)
ip neigh show
```

### Уровень L3: IP-адреса и таблица маршрутизации
```bash
# Посмотреть всю таблицу маршрутизации
ip route show

# Узнать, через какой интерфейс и шлюз сервер отправит пакет до конкретного IP (супер-полезно!)
ip route get 8.8.8.8

# Временно добавить статический маршрут (до перезагрузки)
sudo ip route add 10.20.0.0/16 via 192.168.1.1 dev eth0

# Временно добавить дополнительный IP-адрес на интерфейс
sudo ip addr add 192.168.1.99/24 dev eth0
```

## 2. Утилита `ss` (Socket Statistics — анализ портов и соединений L4)
Работает намного быстрее `netstat`, так как берет данные напрямую из пространства ядра Linux.

```bash
# Показать ВСЕ слушающие (LISTEN) TCP и UDP порты с именами процессов (-p) и без резолва DNS (-n)
sudo ss -tulnp

# Посмотреть своную статистику по всем сокетам (сколько ESTABLISHED, TIME_WAIT и т.д.)
ss -s

# Найти все активные подключения к конкретному порту (например, SSH 22 или HTTPS 443)
ss -tn state established '( dport = :443 or sport = :443 )'

# Посмотреть очередь переполнения сокетов (Recv-Q / Send-Q — если растут, приложение не успевает разгребать трафик)
ss -lnt
```

## 3. Утилита `ethtool` и проверка Bonding (Агрегации портов L1/L2)
Незаменимы для проверки физического подключения, скорости порта и отказоустойчивых связок сетевых карт.

```bash
# Проверить физический линк (Link detected: yes/no), скорость (1000Mb/s) и дуплекс (Full)
sudo ethtool eth0

# Посмотреть детальную статистику аппаратных ошибок сетевой карты (CRC, rx_missed, fcs)
sudo ethtool -S eth0 | grep -iE "err|drop|miss|crc"

# Помигать светодиодом на порту сетевой карты 10 секунд (чтобы инженер в дата-центре нашел нужный сервер в стойке!)
sudo ethtool -p eth0 10

# Проверить статус агрегированного интерфейса (Bonding / LACP): какой кабель активен, а какой упал
cat /proc/net/bonding/bond0
```

## 4. Файрволы в Linux (`iptables`, `nftables`, `ufw`) и контрэк (`conntrack`)
В Linux пакеты фильтруются на уровне ядра (**Netfilter**). В NOC чаще всего нужно быстро проверить, не блокирует ли файрвол нужный порт и не переполнена ли таблица сессий.

### Основные цепочки в `iptables` (таблица `filter` по умолчанию)
* **`INPUT`:** Пакеты, предназначенные **самому этому серверу**.
* **`OUTPUT`:** Пакеты, отправляемые **с самого этого сервера**.
* **`FORWARD`:** Транзитные пакеты, проходящие **через сервер** (если Linux работает как роутер или хост для Docker/VM).

```bash
# Посмотреть все правила файрвола с номерами строк и счетчиками сработавших пакетов (-v -n)
sudo iptables -L -v -n --line-numbers

# Посмотреть правила NAT (проброс портов и маскарадинг)
sudo iptables -t nat -L -v -n

# Если используется современный nftables — посмотреть весь набор правил
sudo nft list ruleset

# Если используется Ubuntu/Debian с надстройкой UFW
sudo ufw status verbose
```

### Авария `conntrack: table full` (Переполнение таблицы соединений)
На высоконагруженных серверах и NAT-шлюзах ядро отслеживает каждую сессию в таблице `nf_conntrack`. Если она заполняется на 100%, ядро начинает молча отбрасывать новые пакеты!
```bash
# Проверить текущее количество записей и максимальный лимит (если числа почти равны — это авария!)
cat /proc/sys/net/netfilter/nf_conntrack_count
cat /proc/sys/net/netfilter/nf_conntrack_max

# Экстренно увеличить лимит в памяти (до перезагрузки)
sudo sysctl -w net.netfilter.nf_conntrack_max=524288
```

## 5. Замер пропускной способности (`iperf3`), системные логи и DNS
* **Проверка реальной скорости канала (`iperf3`):** Запускается на двух серверах (один как сервер `iperf3 -s`, второй как клиент `iperf3 -c IP_СЕРВЕРА -P 4`). Показывает реальную пропускную способность в Мбит/с или Гбит/с и количество ретрансмиссий TCP.
* **Поиск физических обрывов линка в логах ядра:**
  ```bash
  # Показать сообщения ядра с читаемым временем (видно, когда интерфейс падал в Link is Down)
  sudo dmesg -T | grep -iE "link|eth|bond|conntrack"
  ```
* **Проверка DNS в системе:**
  * `/etc/resolv.conf` — адреса DNS-серверов (`nameserver 8.8.8.8`).
  * `/etc/hosts` — локальные статические записи (имеют высший приоритет перед DNS).
  * `resolvectl status` — статус DNS в современных системах с `systemd-resolved`.

## Практика NOC: чек-лист диагностики сетевой проблемы на Linux-сервере
Если на сервере пропал интернет или не открывается сервис, проверяем по порядку:
1. `ip -br a` — подняты ли интерфейсы (`UP`) и есть ли на них нужные IP-адреса.
2. `sudo ethtool eth0` и `dmesg -T | tail` — есть ли физический сигнал (`Link detected: yes`) и не «моргал» ли линк.
3. `ip r` и `ip route get 8.8.8.8` — есть ли маршрут по умолчанию (`default via ...`).
4. `ip neigh` — виден ли MAC-адрес шлюза (`REACHABLE`, а не `FAILED`).
5. `sudo ss -tulnp` — слушает ли приложение нужный порт (`0.0.0.0:443`, а не только локальный `127.0.0.1:443`!).
6. `sudo iptables -L -v -n` и `nf_conntrack_count` — не растут ли счетчики `DROP` и не забита ли таблица соединений.

## Частые вопросы на собеседовании
* **В чем разница между действиями `DROP` и `REJECT` в файрволе?** `DROP` молча отбрасывает пакет без ответа (клиент долго ждет и получает *Connection timed out*). `REJECT` отбрасывает пакет и отправляет клиенту отказ (`ICMP Port Unreachable` или `TCP RST`), поэтому клиент сразу получает *Connection refused*.
* **Что означает, если в выводе `ss -tulnp` сервис слушает адрес `127.0.0.1:8080` вместо `0.0.0.0:8080`?** Сервис принимает подключения **только локально с самого себя** (Loopback). Подключиться к нему по сети с другого компьютера не получится, пока в конфиге приложения не поменять адрес прослушивания на `0.0.0.0` (все интерфейсы).
* **Как в Linux временно включить маршрутизацию пакетов между интерфейсами (превратить сервер в роутер)?** Включить параметр ядра `ip_forward`: `sudo sysctl -w net.ipv4.ip_forward=1`.
